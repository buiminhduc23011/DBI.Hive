## 2026-02-01 - [Search Component Accessibility]
**Learning:** Custom search dropdowns using divs and buttons often lack semantic ARIA roles (combobox/listbox) and accessible labels for icon-only buttons (like Clear/Search).
**Action:** Always verify custom interactive components with ARIA roles and ensure all icon-only buttons have descriptive aria-labels.
## 2026-02-01 - [ARIA Labels for Icon-Only Buttons and i18n Localization]
**Learning:** When adding ARIA labels to icon-only buttons, it is critical to also apply `aria-hidden="true"` to the inner SVG icons to avoid redundant screen reader announcements. Additionally, when defining the `aria-label` text, always use the existing `t()` translation function from `i18nStore` and ensure any new translation strings are properly registered in `client/src/stores/i18nStore.ts`, rather than hardcoding bilingual ternary operators in the component. Finally, `pnpm install` side effects (like modified lock files) must be cleanly reverted before committing to adhere to strict boundary rules.
**Action:** Consistently enforce the pairing of `aria-label` on buttons and `aria-hidden="true"` on their child icons. When introducing new accessible text, properly register it in the translation store (`i18nStore.ts`) instead of injecting inline ternary conditions. Always inspect Git status and stage changes selectively to prevent lock file pollution.
